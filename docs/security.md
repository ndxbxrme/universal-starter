# Security and privacy

Threat boundaries: shared renderer content cannot gain Node/filesystem/IPC privileges; platform adapters expose only documented methods. Electron uses sandbox/context isolation/Node disabled, validated sender/main-frame checks and allowlisted bounded argument shapes. The preload exposes version, platform, sandbox state and allowlisted invoke methods. Native file dialogs return metadata only. app:// serves files confined to the bundled asset directory, including realpath/symlink checks. Navigation/window creation/downloads/renderer permissions are restricted; external support links require the configured HTTPS path. Production CSP has no eval/inline/remote code allowances. Tests check actual sandbox state and Node-global absence.

Capacitor releases use bundled assets with no server URL or cleartext exceptions. Android has a direct Gradle release guard; iOS has an Xcode Release-phase guard. LAN URLs/debug cleartext are temporary Android development-only files and are restored on exit or by sync/recovery commands. Treat wireless ADB/Vite as trusted-LAN development tools, never public services. Permissions are documented in platform guides. Prompts occur on user gestures; denials/unsupported/cancellation/failures are surfaced through typed errors. No native success is inferred from browser mocks.

No backend, telemetry, analytics SDK, account system or push server is included. Diagnostics omit unique IDs/device names and stay local; event logs are memory-only. The original file picker returns metadata only. Camera/audio demos read temporary local media for preview/playback; they do not upload it. GPS values stay in memory and are excluded from diagnostics. A user may explicitly open coordinates in Google Maps or export audio through a share/save dialog. Theme is local storage; native demo preferences are UserDefaults/SharedPreferences. Browsers may expose API interfaces without functional hardware/OS support; the app reports actual call errors. See privacy-policy-template.md and review data handling after replacing demo logic.

Credential utilities reference client-controlled external files/OS stores, suppress sensitive validation errors, use environment/stdin for passwords, persist only allowlisted non-secret references with restrictive permissions, and require target/name confirmation for optional GitHub secret sync. Actual Windows signing uses the OS certificate store; Apple notarization uses a Keychain profile so no password arguments are sent. Signed Mac notarization is a separate opt-in upload requiring client approval. No keys/certificates have been uploaded or production identities generated by this implementation.

CI PRs have no signing secrets and do not use privileged PR triggers. Protected release environments/runners require owner configuration and reviewed tags. SHA-pinned actions, npm ci, lockfile, audit and secret-inventory checks reduce supply-chain risk; they do not prove the absence of every vulnerability. Audit fails at moderate severity; update packages with compatibility review and affected tests. Desktop updating is disabled until trusted signing/feed verification exists.

Report security issues privately to the client/repository owner's configured contact, not in public issues with keys, tokens or sensitive diagnostics. Stop distribution of compromised artifacts, revoke/rotate with the client owner and follow credentials.md recovery guidance.

The microphone is the only newly granted Electron renderer permission: trusted main frame, audio-only media request, explicit confirmation. Video/screen capture/subframes/other origins remain denied. Audio export is bounded to 8 MiB decoded bytes and native-dialog-selected destinations. Mobile RECORD_AUDIO and foreground location permissions are prompted only by actions; no background tracking/recording service is enabled. Native preferences accept only the two documented non-secret keys. Motion listeners and recorder resources stop on inactivity/teardown. See device-showcase.md for temporary-file and interrupted-camera limits.
