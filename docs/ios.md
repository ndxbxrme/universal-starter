# iOS

Use macOS with Xcode 26+, its command-line tools and an installed iOS simulator runtime. Minimum app target: iOS 15. Capacitor 8.5.3 uses Swift Package Manager with an exact SDK version and local npm plugin package paths. `npm ci` must run before Xcode resolves packages. Linux/Windows can sync assets but cannot compile or sign iOS apps.

Run `npm run dev:ios` to build/sync the same bundled SPA and open Xcode. Select the App scheme and a simulator, then Run. `npm run ios:open` just opens the existing project. `npm run build:ios` produces an unsigned simulator app at artifacts/ios/Build/Products/Debug-iphonesimulator/App.app. Optionally select a simulator UDID with `-- --device UDID`. List targets using `xcrun simctl list devices available`; boot with `xcrun simctl boot UDID`. The simulator .app is not an iPhone IPA. Core navigation works offline; web browser hot reload remains `npm run dev`. The iOS command deliberately uses bundled assets, not a remote server.

Install Maestro CLI 2.12.0 (see testing.md), boot a simulator, then `npm run test:ios -- --device UDID`. It builds, installs, launches, navigates and invokes the real Device plugin. Screenshots/log output are in artifacts/ios-smoke. Linux reports an actionable macOS prerequisite error. Simulator success would not prove iPhone haptics, signing, wireless deployment or TestFlight.

For a real iPhone: open Xcode Signing & Capabilities, select a client-controlled development team, keep a unique registered bundle ID, select the phone, enable Developer Mode on the phone and approve trust prompts. Xcode may require initial cable pairing before wireless use. In Window → Devices and Simulators, enable network connection where offered. Both devices must be reachable on the same trusted network. Wireless deployment support depends on Xcode/device pairing; USB-free initial iPhone setup is not guaranteed.

For signed release, set APPLE_TEAM_ID and IOS_EXPORT_OPTIONS to a reviewed ExportOptions.plist outside the repo; install the appropriate signing identity/private key and matching provisioning profile in your keychain. `npm run build:ios:release` archives to artifacts/App.xcarchive and exports to artifacts/ios-release using xcodebuild. Choose app-store-connect, development or ad-hoc export according to current Xcode options and the client's account entitlements. A successful export still requires codesign verification and a real-device test. See credentials.md and store-publishing.md for client ownership and TestFlight prerequisites.

Permissions: local notification authorization is requested on a user gesture; denial directs users to Settings. No camera, contacts, location or photo library permissions are requested. File selection uses the WebView system document picker; clipboard writes and text sharing use official plugins. No unique device ID is requested. On iOS, use shared navigation/browser history; native swipe-back behaviour depends on the WebView and OS. Safe areas and reduced motion are respected.

PrivacyInfo.xcprivacy declares no tracking, no collected data and no app-specific required-reason APIs. The bundled Capacitor SDK supplies its own manifests. Reviewed plugin 8.x sources do not use disk-space/uptime/UserDefaults APIs in these demos; re-review manifests whenever adding plugins or business logic. App Store privacy approval is not verified here. Local Notifications foreground presentation is configured to show an alert; scheduled inexact notification timing may vary by OS.

If Xcode cannot resolve packages, verify npm dependencies, selected Xcode (`xcode-select -p`) and network access to the exact Capacitor Swift package. Run the first-launch Xcode setup and install a simulator runtime. Do not remove/recreate the native project to fix signing. Commit the Xcode-generated Package.resolved after the first successful Mac resolution. It cannot be generated honestly on this Linux host.

Release builds also run scripts/check-native.mjs from an Xcode build phase, with environment-variable log dumping disabled. Node must be on the build environment PATH (or NODE_BINARY set). This rejects development URLs/CSP and Pages assets even when archiving directly in Xcode. A Linux syntax parse is not proof that this phase or Swift compiles on macOS.

The device showcase adds official Geolocation, Camera, Browser and ScreenOrientation SPM plugins, a registered StarterViewController/StarterDevicePlugin Swift source and Settings.bundle in the Xcode resource phase. Location, camera, photo-library, microphone and motion purpose strings are declared. No background location/audio mode is enabled. Native audio uses AVAudioRecorder; native preferences use the same standard UserDefaults as Settings.bundle, with its required-reason declaration in the app privacy manifest. Compilation, Settings rendering and physical microphone/GPS still require macOS/Xcode/iOS verification. See [device-showcase.md](device-showcase.md).
