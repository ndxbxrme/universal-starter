# Customisation

Edit universal-app.config.json for display/short name, public HTTPS support/site URLs, theme colors, stable X.Y.Z version, independent Android/iOS build numbers, declared targets and default channel. Version suffixes are represented by channel in V1; native marketing versions remain numeric X.Y.Z. Replace all dev.example/example.com values before publishing. Run `npm run config:validate`, `npm run config:sync -- --dry-run`, review, then `npm run config:sync`. Unknown fields (including secrets), URL credentials and invalid identities are rejected. Run setup/icons again after artwork changes and review generated diffs.

The same UI serves every platform. To replace the demo, keep root index.html as Vite's entry and replace src/main.js/app/features/styles with your vanilla SPA, or change its script import to your existing module entry. Keep native integrations behind src/platform; do not import Electron/Capacitor directly from feature views. Relative imported assets are bundled; public assets use import.meta.env.BASE_URL. Keep hash routes for Pages unless you supply a tested server fallback. `npm run build` is always the native-safe bundle; build:web accepts WEB_BASE separately. Re-run keyboard, accessibility, offline, subpath and native smoke tests after replacing the UI.

Edit resources/icon.svg (original MIT artwork master), then `npm run icons:generate`. The generator writes web PNG/SVG, desktop ICO/ICNS, Android adaptive/legacy icons and splash images, and iOS AppIcon/splash catalogs. Splash SVG is generated from that same master plus configured dark background; do not hand-edit generated outputs. Review safe areas/icon masks on real devices and OS launchers.

IDs are initialized to placeholders. Renaming a previously created project is a reviewed migration: `npm run identity:plan` prints exact affected fields and consequences without modifying files. Back up/commit first, use Studio/Xcode refactor tools for native packages/IDs/paths, update canonical/provenance initializedAppId only after review, then sync and rebuild both platforms. Renaming after publication creates a different store app and does not upgrade old installations. Never recreate wrappers destructively to rename. Keep original client signing assets and store identity when existing installations must update.

Before store preparation, review app name/icons, support/privacy pages, bundle/app ID ownership, monotonic build numbers, licenses, permission rationale, screenshots, audience/content ratings, privacy-data declarations and release channel. Account/listing creation and publication require client approval. See credentials.md and store-publishing.md.
